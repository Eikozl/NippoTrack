Runtime layer
-------------
`postgresAdapter.js` presents the existing controller-facing `execute`, `query`, and
transaction interface over `pg`. It translates parameter markers to PostgreSQL `$n`,
returns MySQL-compatible controller result shapes (`rows`, `affectedRows`, `insertId`),
and uses `RETURNING` for identity inserts. Transaction clients retain BEGIN/COMMIT/
ROLLBACK/release behavior.

Explicit PostgreSQL conversions
-------------------------------
* Health: `current_database()` while preserving API response `database: "jlt"`.
* Dashboard: PostgreSQL CURRENT_DATE, date arithmetic, date_trunc('week'), and to_char.
* Goals: PostgreSQL week boundary/date casts and actual boolean writes/filters.
* Review: CURRENT_DATE/CURRENT_TIMESTAMP, date addition, and ON CONFLICT DO NOTHING.
* Structured session writing: PostgreSQL ON CONFLICT ... DO UPDATE with EXCLUDED.
* Search: prepared parameters remain bound; PostgreSQL ILIKE preserves the source
  case-insensitive matching behavior. Japanese/kana normalization and the existing
  romaji ranking helper are unchanged.
* `updated_at` remains enforced by the verified PostgreSQL triggers.
* Connection sessions set America/Santo_Domingo through PostgreSQL startup options,
  so CURRENT_DATE/current-week behavior uses the intended operating timezone.
* PostgreSQL SQLSTATE 23505/23503 maps to the established safe conflict/related-record
  API error contracts.

Preserved API behavior
----------------------
The public routes, payload validation, response fields, pagination, relationship
transactions, review behavior, search ranking, and health response contract remain
unchanged. `goals.is_active` is stored as PostgreSQL boolean but normalized to 1/0 in
controller result rows to preserve the existing client contract.
