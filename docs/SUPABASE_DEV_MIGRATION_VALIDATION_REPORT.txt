========================================================

Date: 2026-08-30
Result: ACCEPTED. Supabase DEV is the cloud PostgreSQL infrastructure for remaining JLT development.

Scope and exclusions
--------------------
* No Vercel configuration, deployment preparation, domain work, or production deployment was performed.
* MariaDB was not changed. It remains a temporary rollback/reference source only.
* The source was the already validated immutable local backup, not a live MariaDB write path.

Connection strategy
-------------------
* The supplied direct admin hostname was not resolvable from this network, consistent
  with the direct endpoint's IPv6 requirement.
* Supabase Shared Pooler / Session mode (port 5432) was selected as the approved IPv4
  fallback for schema migration, transfer, and current persistent local JLT runtime.
* SSL enforcement is active in the Supabase project. The Node configuration requires
  SSL for this target. Certificate pinning/verify-full may be added later with the
  Supabase CA; no password or URL is committed.
* Migration operations and runtime connection strategy remain separate variables:
  `SUPABASE_MIGRATION_URL` should designate the direct admin URL when IPv6 is available;
  `SUPABASE_RUNTIME_URL` should designate the session-pooler URL from IPv4 environments.
  Current local configuration uses ignored `.env.supabase` fields (`POSTGRES_HOST`,
  `POSTGRES_PORT`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`,
  `POSTGRES_TIMEZONE`, `POSTGRES_SSL`).
* DEV and future PROD must stay separate Supabase projects with separate credentials,
  migration execution, validation records, and no shared test data.
