3. P0 - FIX STORED XSS RISK
======================================================================

CURRENT PROBLEM:
Frontend rendering currently uses innerHTML with values returned from the
database, including vocabulary, grammar, sessions, and kanji data.

This allows stored user content to become executable HTML.

REQUIRED CHANGES:

1. Do NOT insert database/user-supplied content using innerHTML.

2. Prefer:
- document.createElement(...)
- element.textContent = value

3. If templates are retained, user-controlled values must be escaped before
   insertion. textContent is preferred.

4. Empty-state markup may use static innerHTML only when no user-controlled
   data is interpolated.

5. Replace list rendering with safe DOM construction.

BAD:

    li.innerHTML = `
      <strong>${item.word}</strong>
      <div>${item.meaning}</div>
    `;

GOOD:

    const strong = document.createElement('strong');
    strong.textContent = item.word;

    const meaning = document.createElement('div');
    meaning.textContent = item.meaning;

    li.append(strong, meaning);

ACCEPTANCE TEST:

Insert a record containing:

    <img src=x onerror=alert('xss')>

The UI must display it as text.
It must NOT execute.

10. P1 - USE TRANSACTIONS FOR MULTI-TABLE SESSION WRITES
======================================================================

CURRENT PROBLEM:
Creating/updating a session plus its relationships can modify multiple tables.

REQUIRED:

POST /api/sessions
PUT /api/sessions/:id

must use a transaction when modifying:
- study_sessions
- session_vocabulary
- session_kanji
- session_grammar

Required flow:
1. get connection from pool
2. BEGIN
3. insert/update parent session
4. validate related IDs
5. update junction tables
6. COMMIT

On failure:
- ROLLBACK

Always release connection.

Pseudo-pattern:

    const connection = await pool.getConnection();

    try {
      await connection.beginTransaction();
      ...
      await connection.commit();
    } catch (error) {
      await connection.rollback();
      throw error;
    } finally {
      connection.release();
    }

ACCEPTANCE TEST:
Force one junction insertion to fail.
No partial session/relationship state should remain.
